## Rules

- Full fields; no `…` truncation.
- Relationship may be `[assumption]`; label it.
- One table per finalist, with the same rows in the same order.
- The index is for navigation; the per-direction table is the evaluation artifact.

## Repeated full runs

When the user asks for ten runs or a full run per card, every run also gets its own standalone table:

- add `Run` and `Frame` rows at the top;
- keep the same Who/What/evidence/kill rows;
- write it to `runNN/04_POSITIONING_TABLE.md`;
- do not bury it inside `01_DECK_OUTLINE.md` or answer with an index only.

The user evaluates the positioning table, not the index.
